# ADR 012 (учебный): канон в git, не брендовый агент

**Статус:** принято  
**Дата:** 2026-09-16

## Контекст

Фраза «собрать своего агента» смешивает три вещи: Cursor SDK / Automations (свой runtime), курс (студент кладёт rule / skill / RAG / ADR в git), configurator `assemble` (репо с паком в корне). Развилка: отдать учащимся готового «QA-агента с harness внутри» — или оставить канон файлами, которые читает уже существующий Cline / Cursor.

Номер **012** — только пак. Не путать с monorepo `docs/adr/012-allure-report-kit.md`.

## Решение

1. Учащимся не собирать отдельный агент (runtime, SDK, бренд-личность с каноном внутри). Агент уже есть: Cline или Cursor. Канон — harness в корне репо (ADR 011).
2. Три смысла не смешивать: SDK ≠ курс ≠ assemble.
3. Курс (занятия 2–5) = студент собирает и видит harness. Чёрный ящик ломает занятие 1 (`testE2e`) и лабораторию Skill / Rule / RAG.
4. Продукт `assemble` = OS + cell + выбранные agents, без `course`. Это репо, не бинарь.
5. Безголовый «пиши тесты по канону» — mill / java-ai-golden (eval). Не ежедневный агент студента.
6. Cursor SDK / Automations — не поток 2. Позже опционально рядом с занятием 5, не вместо 2–4.

## Последствия

- Не заводить школьный QA-агент как учебный продукт.
- Не класть канон только в system prompt / custom GPT / SDK без файлов в git.
- `AGENTS.md` — тонкая роль; лимиты и шаги — rules / skills / RAG.
